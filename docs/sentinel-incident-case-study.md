# Sentinel Incident Response Case Study

## Scenario

A controlled failed Azure control-plane operation was generated in the NorthStar lab to validate monitoring, detection, and incident-response workflow.

## Telemetry Pipeline

Azure Activity Log → Log Analytics workspace → Microsoft Sentinel analytics rule → Sentinel incident

- SOC workspace: `NorthStar-SOC-Workspace`
- Source resource group: `NorthStar-Azure-RG`
- Analytics rule: `NorthStar - Failed Azure Control Plane Operation`
- Detection cadence: every five minutes
- Severity: Medium

## Detection Logic

```kql
AzureActivity
| where ResourceGroup =~ "NORTHSTAR-AZURE-RG"
| where ActivityStatusValue =~ "Failure"
| project TimeGenerated, OperationNameValue, ActivityStatusValue, ResourceGroup
```

## Investigation Outcome

- Incident ID: `54db208e-cd16-49f1-bb38-e3ac13816a54`
- Incident status: Closed
- Classification: Benign positive
- Classification reason: Suspicious but expected

The alert was generated by an intentional validation activity, not malicious behavior. The incident was reviewed and closed with the appropriate classification.

## Skills Demonstrated

- Azure Activity Log monitoring
- Log Analytics and Microsoft Sentinel integration
- KQL-based detection logic
- Alert triage and incident classification
- Terraform management of diagnostic settings and analytics rules

This is portfolio and lab work. It demonstrates a repeatable SOC detection and triage workflow in Azure.
